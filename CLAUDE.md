# Клубок

Кроссплатформенный мад-клиент для [Былин](https://bylins.su): функции JMC (триггеры, алиасы,
переменные, скрипты) и MudMapper (автомаппинг, путь, спидволк) в одном приложении.
Цель — Windows, Linux, Android (позже iOS). **Сейчас собираем только портативную версию.**

## Общение и стиль

- Общение, комментарии и документация — по-русски. Идентификаторы — по-английски.
- Владелец проекта **не знает Rust**. Пиши простой Rust и поясняй неочевидное в комментариях:
  - владеющие типы (`String`, `Vec`) в структурах, `.clone()` не стесняясь, без явных лайфтаймов;
  - сообщения через enum'ы и каналы вместо `Arc<Mutex<…>>`;
  - ошибки: `thiserror` в библиотечных крейтах, `anyhow` в бинарниках;
  - никакого `unsafe` (запрещён в workspace lints).
- Термины домена — термины игрока: `Room`, `Exit`, `Zone`, `Trigger`, `Alias`, `Prompt`, `Speedwalk`.

## Архитектура (облегчённый DDD)

Ограниченные контексты = крейты в `crates/`:

| Крейт | Роль |
|---|---|
| `klubok-proto` | telnet, MCCP, кодировки, переводы строк, ANSI → `StyledLine`. Только чистые функции, без IO и async. |
| `klubok-automation` | триггеры, алиасы, подсветка, переменные, таймеры, rewrite (gag/sub/merge/collapse, пустые строки), импорт JMC |
| `klubok-map` | комнаты, выходы, зоны, текущая комната, поиск пути. Самая богатая доменная модель. |
| `klubok-core` | прикладной слой: `Session` — единственный владелец состояния; входы/выходы — `SessionInput`/`SessionOutput` через mpsc |
| `klubok-mm2` | чтение карт старого MudMapper (`.mm2`, потоки Delphi TPF0) и перевод в `klubok-map` |
| `klubok-cli` | консольный клиент для отладки ядра без UI |
| `app/` | Tauri 2 + SvelteKit 5/TS. Rust-часть в `app/src-tauri` (крейт `klubok`, член workspace). Фронтенд «тупой»: только рисует и шлёт команды. |

Правила:
- Зависимости только «внутрь»: `proto` ни от кого не зависит; `core` связывает контексты; UI зависит от `core`.
- Порты (трейты) только где окупаются: `MapStore` (SQLite / в памяти), `Clock` (реальное / управляемое время в тестах).
- **Выходы однонаправленные.** Из A на север в B не означает, что из B на юг — в A. Обратный выход
  записывается только когда его реально прошли; маппер ничего не достраивает сам.
- Маппер и сырой лог видят исходные строки; rewrite влияет на показ и пользовательские триггеры.
- Строки в UI отправляются пачками (~16–30 мс), не по одной.

## Команды

```bash
cargo build                      # сборка
cargo test                       # тесты
cargo clippy --all-targets       # линтер — должен быть чистым
cargo run -p klubok-cli          # консольный клиент
./scripts/server.sh start|stop|status|log   # локальный сервер Былин (исходники в ../bylins-server)
./scripts/build-windows.sh [папка]           # портативный .exe через cargo-xwin (по умолчанию dist/windows)
(cd app && npm run check)                    # проверка типов фронтенда
./scripts/app-headless.sh start|shot|stop    # окно на Xvfb :99 для скриншотов; клики — DISPLAY=:99 xdotool
```

## Автоматизация, профили, пароли

- `klubok-automation::Automation` — интерпретатор команд JMC: `;`-разбиение вне `{}`, алиасы (`%0` — все
  аргументы, `%1…` — слова), `#action` (обычные шаблоны с `%N` и `/regex/флаги`; в регулярках `%0` — первая
  группа, как в JMC), `#var`, `#if`, `#math`, `#highlight`, `#hot`, `#gag`, `#substitute`, `#group`.
  `$переменные` в определениях не подставляются — только при выполнении/проверке.
- Неизвестные команды из `.set` сохраняются как есть (`preserved`) и пишутся обратно — ничего не теряем.
- `#script` — JavaScript (rquickjs/QuickJS, фича `parallel`, чтобы `Automation` был `Send`), объект `jmc`
  как в JMC; вызовы `jmc.*` копятся и выполняются после скрипта. Лимиты: 1 с, 32 МБ.
- Таймеры как в JMC 3.6: `#N:задержка {…}` (десятые секунды), `#abort`, `#wait`, тикер `#tickon/#tickset`,
  плюс своё `#delay {сек} {…}`. Движок часов не читает: сессия зовёт `set_now`, а по `next_deadline` —
  `SessionInput::Timers`.
- `#merge {начало} {конец|число строк} {разделитель}` — склейка строк (своё расширение); промпт закрывает
  незаконченную склейку. Склеенная строка идёт дальше в замены, триггеры и подсветку.
- Окна вывода JMC: `#woutput N [{цвет}] {текст}`, `#wname`, `#wshow`, `#wclear` (N = 0…9) → `Effect::Window`
  → колонка справа. `#wname` сохраняется в настройках. Без своих `#hot` цифровой блок ходит (NUM8 — север…).
- Редактор настроек (`AutomationEditor.svelte`) разбирает текст JMC на поля; у подключённого профиля
  сохранение уходит в сессию (`SessionInput::ReplaceAutomation`).
- Пока идёт вход (кодировка не выбрана или автовход не завершён), триггеры не запускаются: в `.set` JMC
  бывают свои триггеры входа, они ломают автовход.
- Профиль: `<данные>/profiles/<id>/profile.toml` + `automation.set` (формат JMC, UTF-8). Данные — в
  `klubok-data` рядом с exe (портативно), иначе стандартная папка приложения.
- Пароли — никогда в профиле: Windows/macOS — системное хранилище (`keyring`), иначе `secrets.toml`
  без шифрования. Пароль и «Имя Пароль» на входе отправляются `SessionInput::Raw` (без алиасов и `#`).
- **В реальных `.set` владельца есть пароль открытым текстом** — не копировать такие файлы в репозиторий,
  `recordings/` и тестовые фикстуры; временные копии удалять после проверки.

## Карта

- `klubok-core::mapper::Mapper` живёт в `Session`: MSDP `ROOM` → `Map::update_from_msdp` → запись комнаты в
  `SqliteStore` (`<данные>/maps/<profile.map>.sqlite`, профили одного мира делят карту) → `SessionOutput::Map`
  (комнаты текущей зоны и уровня) → `MapPanel.svelte`.
- После входа сервер не шлёт ROOM, пока игрок не шагнёт, — сессия на первом игровом промпте (`…>`)
  просит MSDP `SEND ROOM`. **Раньше нельзя**: до входа у сервера нет персонажа, обработчик ROOM его
  разыменует.
- Карты «неровные»: если клетка новой комнаты занята комнатой той же зоны, зона раздвигается
  (`Map::make_room_at`: сдвигается клетка и всё строго дальше по ходу, поперечная линия остаётся).
  Слипшиеся раньше комнаты разводятся при входе (`Map::separate`) и командой `#map fix`.
- Панель карты (`MapPanel.svelte`) в стиле MudMapper. Режим правки ✎: выделение кликом/Shift/рамкой,
  перетаскивание по сетке, стрелки, уровни, Delete, цвет, пометки (`dt`, `flydt`, `aggro`, `nostep`) →
  `map_edit` → `SessionInput::MapEdit` → `Mapper::edit`. Удаление не трогает выходы других комнат.
- Скрытые выходы: маппер помнит отправленные направления (`note_sent`) и, если шаг привёл в новую комнату
  без такого выхода в MSDP, записывает выход `hidden`. Только если шаг однозначен (в очереди один);
  промпт без смены комнаты выбрасывает самый старый шаг (стена).
- `#go <vnum|часть названия>` — путь по шагам: следующий шаг уходит, когда пришёл `ROOM` ожидаемой комнаты;
  попали не туда — путь перестраивается (до 3 раз). `#stop`, `#map` (find/note/exit/unexit).
- Импорт MudMapper: у каждого `.mm2` своя сетка, поэтому карта рисуется по номеру зоны (`vnum / 100`).
  Комнаты без vnum получают выдуманные номера от 3 000 000 000 — сервер их не пришлёт.
  Карты владельца: `/mnt/c/Users/Alex/Desktop/mud/mudmapper/Maps/Былины` (436 файлов, ~36 тыс. комнат);
  проверка: `cargo run --release -p klubok-mm2 --example to_map -- <папка> [--out=файл.sqlite] [от до]`.

## Тестирование

- Парсеры в `proto` покрываются юнит-тестами на байтах.
- Реальный трафик записывается в `recordings/` и прогоняется через ядро (record/replay) — без сети.
- Таймауты (merge, тикеры) тестируются через управляемый `Clock`, не через `sleep`.
- Для ручной проверки — локальный сервер: `./scripts/server.sh start`, затем `cargo run -p klubok-cli`.
- Изменения интерфейса проверяй глазами: `scripts/app-headless.sh start`, подключение кликом через xdotool,
  `scripts/app-headless.sh shot` и Read скриншота.
- Ввод: после отправки строка очищается (как в JMC). Пароль (по промпту) и «Имя Пароль» на входе
  не попадают в историю и маскируются в эхе.
