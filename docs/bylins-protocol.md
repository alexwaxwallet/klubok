# Протокол сервера Былин: что важно клиенту

Выписано из исходников [bylins/mud](https://github.com/bylins/mud) (коммит `36ec71b`, BRusMUD 0.2.27)
и проверено на локальном сервере. Пути — от `src/` исходников сервера.

## Подключение

Сразу после подключения сервер шлёт `IAC WILL MSDP(69)`, `IAC WILL COMPRESS2(86)`, `IAC WILL COMPRESS(85)`,
затем меню кодировок в ASCII и ждёт одну цифру (без GA).

## Кодировки (`engine/structs/structs.h:76-84`)

`0` KOI8-R, `1` cp866, `2` cp1251 (JMC/MMC), `3` cp1251 zMUD, `4` cp1251 «я»→«z», `5` UTF-8, `6` старый zMUD, `9` — показать пробы.
**Клиент выбирает `5` (UTF-8).** Внутри сервер работает в UTF-8. В cp1251 байт 0xFF («я») экранируется как `IAC IAC`.
Буква «ё» на выходе всегда заменяется на «е».

## Telnet-опции

| Опция | Поддержка |
|---|---|
| MCCP v2 (86) | да: на `DO` → `IAC SB 86 IAC SE`, дальше zlib-поток |
| MCCP v1 (85) | да, но маркер нестандартный: `IAC SB 85 WILL SE` |
| MCCP3 | нет |
| MSDP (69) | да (`engine/network/msdp/`) |
| NAWS (31) | только в ответ на `WILL NAWS` клиента |
| GMCP, MSSP, EOR, TTYPE, CHARSET, ECHO, SGA, MXP | нет; на запросы **не отвечает вовсе** — молчание = отказ |

Работает только первая принятая версия MCCP; `DONT` завершает поток.

**Подвох:** неизвестные `DO`/`DONT`/`SB` от клиента остаются во входном буфере сервера и попадают в текст команды.
Клиент **не должен** слать инициативные `DO`/`SB` для опций, которые сервер не предлагал. Разбор IAC на сервере
останавливается на байте `\0`.

Пароль вводится без `WILL ECHO` — маскировать поле пароля клиент должен сам, по тексту запроса.

## MSDP

Команды: `LIST`, `REPORT`, `UNREPORT`, `SEND`. Переменные: `ROOM`, `EXPERIENCE`, `GOLD`, `LEVEL`, `MAX_HIT`,
`MAX_MOVE`, `STATE`, `GROUP`. Ничего не приходит, пока клиент не сделал `REPORT`.
Сами присылаются `ROOM`, `GOLD`, `EXPERIENCE`, `MAX_HIT`/`MAX_MOVE`; `STATE`, `LEVEL`, `GROUP` вне боя — только через `SEND`.
Строки внутри MSDP — в кодировке клиента.

### ROOM (для маппера, `msdp_reporters.cpp:15-102`)

```
ROOM = { VNUM "4014", NAME "Базарная площадь", AREA "Лесная деревня (1-ая родовая)", ZONE "40",
         FROM_ROOM "4056", FROM_DIRECTION "w", TERRAIN "city",
         EXITS = { n "4011", e "4013", s "4020", w "4056" } }
```

- `ZONE` = `VNUM / 100`. Для зон-копий vnum подменяется: `copy_from_zone*100 + vnum%100`.
- Выходы `n/e/s/w/u/d`, скрытые не передаются. Координат нет — раскладку карты строит клиент.
- `ROOM` **не** приходит, если персонаж слеп, темно, режим слепого игрока, флаг скриптера или флаг комнаты `kMoMapper`.
  Маппер должен уметь работать и без MSDP (по тексту).
- Команда «смотреть» шлёт `ROOM` дважды подряд — дубли убирать.
- `режим маппер` добавляет к названию комнаты `[vnum]` в тексте.

## Промпт, GA, переводы строк

- Промпт (`engine/core/iosystem.cpp:1179-1303`): `NH NM [опыт] Зауч:… Вых:СВЮЗ^v> `, с ANSI, без перевода строки.
- `IAC GA` после промпта — только при флаге персонажа `kGoAhead` (`режим автозавершение`; новым смертным включён).
  EOR не шлётся никогда. Без GA промпт опознаётся по таймауту и/или шаблону.
- Переводы строк — `\r\n`, но в отдельных сообщениях встречается `\n\r`; принимать оба.
- Перед каждой порцией вывода сервер вставляет `\r\n`, в не-компактном режиме — ещё пустую строку перед промптом.
  Отсюда «лишние» пустые строки, которые клиент должен уметь схлопывать.

## Локальный тестовый сервер

`./scripts/server.sh start|stop|restart|status|log [N|-f]|build`, порт 4000. Сборка профиля `dev` (`TEST_BUILD`):
без подтверждения по e-mail, первый персонаж получает 34-й уровень.
Тестовый персонаж: **Тестер / tester2026** (только для локального сервера). Быстрый вход: кодировка `5`,
затем на запросе имени одной строкой `Тестер tester2026`.

## MSDP SEND

`SEND "ROOM"` отвечает текущей комнатой сразу (`msdp.cpp: handle_send_command` → `report`). Слать только
когда персонаж в игре: `RoomReporter::get` берёт `descriptor()->character->in_room` без проверки на null.
После входа/переподключения ROOM сам не приходит до первого шага или «смотреть».

## Состояние персонажа по MSDP

`REPORTABLE_VARIABLES`: ROOM, EXPERIENCE, GOLD, LEVEL, MAX_HIT, MAX_MOVE, STATE, GROUP (`msdp.cpp`).
- Сами (после `REPORT`) приходят при изменении: EXPERIENCE, GOLD `{POCKET, BANK}`, MAX_HIT, MAX_MOVE
  (проверяются перед каждым промптом), GROUP (в бою и при смене группы). LEVEL — только по `SEND`.
- `STATE {CURRENT_HP, CURRENT_MOVE, CURRENT_MANA?}` сервер **никогда не шлёт сам** — только на `SEND`.
  `CURRENT_MANA` есть лишь у «маначных» классов; максимума маны в MSDP нет (`MAX_MANA` не зарегистрирован).
- GROUP — массив таблиц `{NAME, HEALTH (%, шаг 10), MOVE (%), IS_HERE, MEM_TIME (сек), AFFECTS (буквы
  О П Д Н С Л В Т), ROLE (leader/pc/npc), POSITION}`; вне группы — пустой массив.
- Клиент: на первом игровом промпте `REPORT`+`SEND` всех, затем `SEND STATE` при каждом изменённом промпте.
